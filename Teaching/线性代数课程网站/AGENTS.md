## 1. 项目目标与工作边界

这是纯静态的中文线性代数课程网站，供学生阅读讲稿改编的知识页、查看公式和图片、记录学习进度。运行网站不需要 Node.js、数据库、账号或在线服务。Node.js 用于维护阶段的页面生成、测试及可选的本地转换工具。

- 沿用普通 HTML、CSS、JavaScript；不要为常规修改引入框架、打包系统或 npm 依赖。
- 保持本地 MathJax、本地图片和相对路径，使网站可离线阅读、可部署到个人主页子目录。
- 界面使用中文，数学符号、原讲稿中的英文名称和缩写按内容需要保留。
- 用户当前要求确定修改范围。不要顺手重排教学内容、合并知识页、清理未知文件或覆盖用户未完成的修改。
- 修改教学内容时核对相应 TeX 正文；修改网页不会同步修改讲稿，修改讲稿也不会自动更新网页。
- 没有实际执行的测试、浏览器检查或发布，不得报告为已完成。

## 3. 源文件与生成文件的关系

```text
js/course.js ───────────────┐
content/**/*.html ──────────┼─ scripts/build-lessons.js ── chapters/**/*.html
第一章模板 ────────────────┘             │
                                        └─ build-additional-chapters.js

index.html + chapters/ + css/ + js/ + assets/ → 可发布的静态网站
```

`content/` 是正文的维护入口；`chapters/` 是生成结果。正文会复用于独立知识页、子节整节阅读和整章阅读。修正文时只修改生成页面，会在下次生成时丢失。

生成器由课程目录驱动，不会自动扫描新增 HTML。新增文件但未登记目录，不会自动出现新知识页。子节目录与整节阅读目前合并在子节 `index.html`，`readingPath` 通常与 `path` 相同，不要凭旧习惯新增独立 `all.html`。

第一章与后续章节使用不同生成实现。修改全站页头、按钮、脚本引用或公共壳层时，要分别检查两套生成路径和首页，不能只改一个模板。

第一章整章构建依赖模板中的小节边界注释、锚点和匹配结构。尤其是 `<!-- 1.x 对应讲稿` 等标记，不能作为“无用注释”删除；生成器找不到边界会报错。

### 4.2 数据生成方式

- 章节包含 `id`、`number`、`title`、`description`、`path` 等字段，子节数组是 `lessons`。
- 子节包含 `id`、`number`、`title`、`description`、`path`、`readingPath`、`pages`，第一章还使用 `anchor`、部分 `legacyPath`。
- 知识页的 `id` 当前由 `section.id + '-' + page.slug` 生成；`path` 根据子节路径和 slug 生成，`number` 根据页序生成。
- 第一章以具名 slug 登记，例如 `what-is-a-vector`。
- 第 2、3 章通过 `additionalSections` 登记标题列表；第 4–9 章通过 `preparedChapters` 的子节标题与页数生成列表。
- 后续章节当前采用位置相关的 slug，例如 `lesson-2-1-1`，子节 id 同样由位置生成。插入或重排可能改变后续内容对应的 id、文件名和收藏地址，不能只移动标题数组。
- 文件开头第 4–9 章虽然写着 `path: null`，后续初始化会设置实际路径。判断是否开放必须看完整初始化后的数据。

发布后的章节 id、子节 id、知识页 id、slug 和旧锚点视为兼容性接口。若任务明确需要重组，先设计保留旧编号的映射或迁移方案，不能让旧学习记录静默关联到另一篇正文。

## 5. 正文、公式和图片的写法

### 5.1 修改正文

正文位置为 `content/chapterXX/sectionXX/<slug>.html`。例如第二章第一节第一页为 `content/chapter02/section01/lesson-2-1-1.html`。

- 文件是 HTML 片段，不添加完整 `html`、`head`、`body`，不重复载入脚本。
- 标题和学习目标由目录及生成器提供，正文不要无意重复整页标题。
- 复用附近正文已有的定义、例题、证明、思考题、表格和 `details` 样式。
- 转换正文通常由 `.tex-converted` 包裹，使用 `css/tex2html.css`。不要仅凭第一章的样式习惯替换后续章结构。
- 正文会合并到整章页；新增 HTML id 必须避免与本章其他片段重复。可使用章节、子节或知识页前缀。
- 局部 `#anchor` 链接要考虑独立页和汇总页是否都存在该目标。跨知识页引用优先使用明确的目标页面路径。
- 不擅自扩大教学范围，核对定义条件、向量或矩阵维数、零除数、实数与复数域等数学约束。

### 5.2 公式示例

```html
<p>设 \(\mathbf{v}=(1,2)\)，考虑向量的长度。</p>
<div class="formula">
  \[ A=\begin{pmatrix}1 & 2 \\ 3 & 4\end{pmatrix}. \]
</div>
```

沿用 `\(...\)` 与 `\[...\]`；现有配置也支持 `$$...$$`。HTML 文本中的小于号写为 `&lt;`。长公式应在容器内滚动，不以大幅缩小文字解决手机溢出。

当前 MathJax 为本地 3.2.2 SVG 版，配置明确加载本地 `color`、`boldsymbol`、`mathtools` 扩展。不要假设任意 TeX 包都可用，也不要添加 CDN 或在线字体。需要特殊命令时先核对配置和实际排版结果。

### 5.3 图片与 SVG

```html
<figure>
  <img src="{{root}}assets/chapter02/example.svg" alt="描述图中数学关系">
  <figcaption>必要的图示说明。</figcaption>
</figure>
```

资源放入对应 `assets/chapterXX/`；`{{root}}` 会按生成页面深度替换。第一章还保留部分旧路径替换兼容逻辑，新内容仍统一采用占位符。

已有中文资源名可能使用 URL 编码，保持路径与真实文件匹配，不要重复编码。修改图形时检查标签、箭头、坐标及数学关系。存在明暗两套图片时要同步核对；转换样式使用 `.tex-figure-light` 和 `.tex-figure-dark` 切换。不要随意删除对应图形的 TeX 源码。

## 6. 学习记录与交互约定

### 6.1 存储与接口

学习记录的唯一读写入口是 `window.CourseProgress`，实现位于 `js/progress.js`。不要在新页面或交互脚本中另建学习记录存储。

- 当前键：`linear-algebra.learning.v2`；旧键：`linear-algebra.learning.v1`。
- 状态结构包含 `version`、`chapters`、`units`、`lastVisited`。
- 单元记录包含 `completed`、`completedAt`、`difficulty`；难度值为 `easy`、`okay`、`hard` 或空。
- 最近阅读记录包含 `unitId`、`visitedAt`。阅读和完成是独立事件。
- v1 章节记录会映射到知识页，保留旧键；v2 存在时优先读取 v2。
- 读取失败时转为当前页内存状态，不自动覆盖损坏的原记录；写入失败时提示无法持久保存。
- 备份包含 `format: "linear-algebra-learning-records"`、`formatVersion: 1` 和 `records`。当前导入是经校验后的状态替换，不是与已有记录自动合并。

常用接口包括 `setUnitCompleted`、`isUnitCompleted`、`setUnitDifficulty`、`getUnitDifficulty`、`setVisited`、`getResumeUnit`、各级 summary、`exportRecords`、`importRecords`。调用前阅读当前函数签名和测试。

主题设置键 `linear-algebra-theme` 由 `js/main.js` 管理，属于界面偏好，不是另一套学习记录。

### 6.2 当前界面行为

- 浏览知识页或滚动整节阅读会更新阅读位置，但不会自动完成。
- 当前 `main.js` 在首次标记已学会前检查难度评价；未评价时给出提醒并返回。生成标记里虽有“可选”文字，实际点击逻辑如此。不要把这一差异当成已经修复。
- 标记完成后留在本页，显示完成效果；不会自动翻到下一页。继续学习与上一、下一知识点是独立操作。
- 小节和章节进度由知识页汇总；记录按浏览器与网站来源隔离，不跨设备同步。
- 测试备份恢复和清空时使用专用测试记录，不要清除用户正在使用的浏览器数据。

### 6.3 DOM 标记也是接口

`main.js` 依赖 `data-chapter`、`data-section`、`data-unit`、`data-reading-unit`、`data-unit-complete`、`data-unit-difficulty`、`data-difficulty-unit`、`data-section-resume`、`data-next-unlearned-link` 等标记。调整生成 HTML 时先搜索其消费者，不能只保留视觉外观而删掉交互标记。

## 7. 课程菜单、主题和响应式

页眉三级菜单由 `main.js` 根据完整课程目录生成，不在每个页面手工维护链接列表。保留“课程首页”的普通链接、手机展开入口、不透明弹出背景和屏幕边缘的子菜单方向调整。

公共颜色和布局优先修改 `css/style.css` 中已有变量。主题通过 `html[data-theme="dark"]` 生效；转换正文还有自身的主题规则。修改共享样式前搜索所有使用位置，避免仅解决一个知识页而破坏其他章节。

涉及视觉或菜单修改时检查宽屏、窄窗口、360px 和 390px 手机宽度，以及明亮、暗色模式。重点检查长标题、长公式、宽表格、触摸入口、键盘焦点、菜单边缘展开和局部横向滚动。

章节与子节页目前有 PDF 打印入口，知识页不显示该按钮，测试对这一点有明确约束。打印还需检查隐藏交互按钮、正文颜色与图形可读性；静态测试通过不能替代打印预览。

## 8. 常见任务的实施步骤

### A. 修改已有知识页

1. 从完整课程目录定位章节、子节、slug 和正文文件。
2. 阅读正文、对应讲稿及必要的图片或样式。
3. 修改片段，保持编号、路径和无关教学内容不变。
4. 生成页面，验证知识页、子节整节阅读、整章阅读的一致性。

### B. 调整标题、说明或目录

1. 修改 `js/course.js` 对应数据来源；第 4–9 章标题由准备数据生成，不能只改运行时不存在的字面对象。
2. 保留既有 id 与 slug；位置相关的章节不能直接插队重排。
3. 生成页面，检查首页地图、页眉菜单、页标题、翻页和继续学习。

### C. 接入新章节或增加知识页

1. 准备正文和资源，确定稳定的命名方案及与讲稿的对应关系。
2. 登记课程目录，检查 slug 与片段文件名一致。
3. 核对生成器是否覆盖新章：当前后续章生成器使用 `/^chapter0[2-9]$/`，因此仅登记第 10、11 章还不够，必须扩展生成范围并检查标题编号等逻辑。
4. 为新范围补足必要的结构、正文一致性和边界导航验证。
5. 生成并测试，再检查移动端、主题、图片、公式和进度。

### D. 修改学习功能

1. 先阅读 `progress.js`、`main.js` 相关处理器和进度测试。
2. 明确存储兼容性和 UI 行为，保留旧字段及迁移能力。
3. 针对实际行为变化补充有意义的测试，覆盖失败情况。
4. 检查正常保存、刷新、撤销、跨标签页、存储禁用、备份恢复和旧记录。

## 9. TeX 转换工作台

转换器位于 `tools/tex2html/`，属于维护工具，不是学生阅读网站所需的服务。使用或修改前阅读它自己的 README 和相关实现。

```powershell
node tools/tex2html/server.js
```

默认入口为 `http://127.0.0.1:4174/tools/tex2html/`，端口可由 `TEX2HTML_PORT` 设置；根目录还有 `启动 TeX 转换器.bat`。仅需要编辑现有 HTML 时无需启动转换器。

浏览器完成主体转换，复杂 TikZ、XY-pic 可使用本机 LaTeX 服务。不要将任意 TeX 转换都视为完整支持。转换后的警告、未解析命令、图片占位和复杂表格要逐项核对。

导出或重新转换不是无损覆盖：保留已有 slug、正文手工修改和共享 CSS，先检查待写文件。转换器不会自动把新增页面登记到课程目录。图形源码与明暗版本应一起维护。

工具 README 中“构建器仅覆盖第一章”的表述已过时；现有主生成器会调用第 2–9 章生成器。修改工具时以源码核实实际能力，不复制旧限制到新实现中。

### 10.1 网站代码或内容修改

```powershell
node scripts/build-lessons.js --check
```

构建会写入生成页面；`--check` 只比较生成内容并报告过期文件，不代替生成。失败时根据具体缺失路径、锚点或断言处理，不通过删除检查来掩盖问题。

纯文档修改不需要为了形式重写全站页面；检查文档引用、命令和代码事实即可，必要时运行只读的 `--check`。若发现原有失败，应如实记录，不扩大任务范围修复无关问题。

### 10.2 现有测试能证明什么

- `site.test.js` 检查生成一致性，并遍历首页和章节 HTML 检查常见 `href`、`src`、锚点与重复 id。
- 正文包含关系和细致的翻页断言主要覆盖第一章，因为测试使用无参数 `getSections()`；不能宣称第 2–9 章已有同等细粒度覆盖。
- 静态链接检查不是完整浏览器资源检查，不能证明 CSS 内资源、公式加载和运行时菜单交互都正常。
- `progress.test.js` 覆盖阅读位置、完成与撤销、迁移、存储失败、损坏记录、备份恢复和难度评价；它不替代按钮在真实页面上的验证。
- 没有浏览器环境时说明视觉与交互未验证，不以 Node 测试通过推断移动端完美。

### 10.3 修改转换器时追加

```powershell
node --test tools/tex2html/tests/*.test.js
```

真实 XeLaTeX / dvisvgm 检查是可选集成测试，仅在依赖可用且任务涉及该路径时按工具 README 执行。不要为普通网站或文档任务安装 LaTeX。

## 11. 常见问题的定位顺序

| 现象            | 优先检查                           |
| ------------- | ------------------------------ |
| 修改正文后页面没有变化   | 是否改了正确的 content 文件、是否重新生成、页面缓存 |
| 新片段没有出现在目录    | 是否登记 course.js，是否在生成器支持范围      |
| 构建提示缺少片段      | 子节编号对应文件夹、slug 与文件名是否匹配        |
| 整章页出现重复 id    | 不同正文片段是否复用同一 HTML id           |
| 深层知识页图片失效     | 是否使用 `{{root}}`、编码是否正确、资源是否存在  |
| 第 4–9 章似乎未开放  | 是否只看了 course.js 顶部而忽略后续初始化     |
| 全站进度只统计第一章    | 是否误用无参数 getUnits / getSections |
| 点击学会没有完成      | 是否尚未选择难度，是否存储失败                |
| 学习记录不同页面不共享   | 是否通过 file:// 打开、浏览器或来源端口是否不同   |
| 样式改动只在第一章生效   | 是否遗漏另一生成器或 tex2html 样式         |
| 公式在联网时正常、离线失败 | 是否引入外部资源或缺少本地扩展                |
| 菜单溢出或暗色图片不可读  | 响应式边界、子菜单方向、主题图形切换             |

## 12. 发布与交付

上传静态网站至少包含 `index.html`、`chapters/`、`css/`、`js/` 和 `assets/`，保持相对层级。无需把 Node 服务或转换工具作为生产运行依赖。只有用户要求发布时才执行发布操作。

维护完成后的回复应简洁说明：

1. 修改了哪些源文件，以及生成文件是否已更新。
2. 用户能看到的行为或内容变化。
3. 是否影响手机端、暗色模式、稳定链接和学习记录。
4. 实际运行的检查及结果；尚未验证的部分和已有失败。

本手册不授权自动改写全站、发布、清空学习记录或变更教学结构。任务中发现文档与代码冲突时，应指出差异，并根据用户意图决定是否修复；不要静默把旧文档行为恢复到当前代码中。
